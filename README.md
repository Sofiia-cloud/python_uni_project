# Roomly — бронирование помещений

Учебный Django-проект для просмотра помещений, поиска свободных дат и
управления бронированиями. Веб-приложение использует Django ORM и SQLite.
Консольное приложение и исходные JSON-файлы предыдущих этапов сохранены.

## Установка и запуск

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python manage.py migrate
python manage.py import_legacy_sqlite
python manage.py runserver
```

Откройте `http://127.0.0.1:8000/`. Для повторного импорта исходных данных
запустите `python manage.py import_legacy_sqlite`. Команда читает старую базу
ПР7 из `data/roomly.sqlite`, переносит первичные ключи и связи в Django-базу
`db.sqlite3`; записи с теми же ID обновляются. Для другого исходного файла
укажите `--source путь\к\файлу.sqlite`.

## Основные страницы

| URL | Назначение |
| --- | --- |
| `/rooms/` | Помещения и число активных бронирований |
| `/rooms/available/?date=YYYY-MM-DD` | Свободные помещения на дату |
| `/rooms/new/` | Создание помещения с фотографией |
| `/rooms/<slug>/` | Страница помещения |
| `/rooms/<slug>/edit/` | Изменение помещения и его фотографии |
| `/bookings/` | Фильтры, поиск, сортировка и пагинация бронирований |
| `/bookings/new/` | Создание бронирования |
| `/bookings/<id>/` | Карточка бронирования и действия |
| `/bookings/<id>/edit/` | Редактирование бронирования |
| `/bookings/statistics/` | Статистика по помещениям и статусам |
| `/admin/` | Административная панель Django |

## Модели и данные

- `rooms.Room`: название, вместимость, уникальный slug и ссылка на карточку.
  `capacity_category` — поле `GeneratedField`, вычисляемое SQLite по
  вместимости помещения; `image` хранит путь к фотографии.
- `bookings.User`: имя и уникальная электронная почта.
- `bookings.Booking`: помещение, пользователь, дата и статус `active`,
  `cancelled` или `completed`.
- Внешние ключи бронирования защищают связанные записи от случайного удаления.
- Структура управляется миграциями Django в каталогах приложений `migrations/`.

Исходная SQLite-база ПР7 не используется Django-представлениями напрямую.
Она сохранена как источник переноса и прежних SQL-примеров. Основная ORM-база
веб-приложения — `db.sqlite3`.

## Формы и проверки

Список бронирований фильтруется по строке поиска, дате, помещению и статусу;
сортировка и параметры фильтра сохраняются при переключении страниц. Форма
создания и редактирования построена на `ModelForm`, проверяет дату и не
допускает двух активных броней одного помещения на одну дату. Отмена доступна
только POST-запросом с CSRF-токеном.

В Django Admin зарегистрированы помещения, пользователи и бронирования.
Настроены поиск, фильтры, сортировка, связанные поля и встроенный просмотр
бронирований в карточках помещений и пользователей. Для входа создайте
администратора командой `python manage.py createsuperuser`.

Для локальной разработки Debug Toolbar подключён по адресу `/__debug__/` и
показывает SQL-запросы страниц. Панель доступна только при `DEBUG = True` и
локальном обращении; в production её следует отключать.

Фотографии принимаются через `ImageField`, хранятся в `MEDIA_ROOT/rooms/` и
показываются на странице помещения. Каталог `media/` исключён из Git.
