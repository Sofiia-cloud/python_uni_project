# Демонстрация Roomly: ПР9–11

## Подготовка

Из корня проекта выполните:

```powershell
python manage.py migrate
python manage.py import_legacy_sqlite
python manage.py check
python manage.py showmigrations
python manage.py runserver
```

## Порядок показа

1. **ORM и модели.** Покажите `rooms/models.py` и `bookings/models.py`:
   поля, первичные ключи, связи `ForeignKey`, обратные `related_name`, статусы
   бронирования `TextChoices`, менеджер `BookingQuerySet`. В `migrations/`
   покажите миграции. Объясните стратегию переноса: старая база ПР7 осталась
   источником, а `import_legacy_sqlite` переносит записи с ID в `db.sqlite3`.
2. **Данные и страницы.** Покажите `/rooms/`, карточку помещения по slug,
   `/rooms/available/?date=2099-01-01` и `/bookings/statistics/`. Обратите
   внимание на свободные помещения, связанные объекты и подсчёт активных
   бронирований по каждому помещению.
3. **ORM-фильтрация.** Откройте `/bookings/`: попробуйте поиск по названию
   помещения или пользователю, фильтр по дате, помещению и статусу, сортировку.
   Если в базе больше десяти записей, переключите страницу и покажите, что
   параметры фильтра сохраняются. В коде покажите `Q`, `filter`, `exclude`,
   `select_related`, `prefetch_related`, `annotate`, `aggregate` и `Paginator`.
   На локальной странице откройте Django Debug Toolbar → SQL и покажите
   сформированные запросы и число обращений к БД.
4. **Админка.** Создайте администратора командой `python manage.py createsuperuser`
   (если он ещё не создан), откройте `/admin/`. Покажите списки помещений,
   пользователей и бронирований, их поиск и фильтры, а также встроенные
   бронирования в карточке помещения и пользователя.
5. **Формы.** Откройте `/bookings/new/`, создайте бронь на будущую свободную
   дату. Затем попробуйте дату в прошлом и занятое помещение: форма должна
   показать ошибки и не сохранить запись. Откройте карточку бронирования,
   измените данные на `/edit/`, затем отмените бронь кнопкой. Покажите, что
   отмена работает POST-запросом с `{% csrf_token %}`, а GET на адрес отмены
   не меняет запись.
6. **Изображение помещения.** На `/rooms/new/` создайте помещение и выберите
   изображение; убедитесь, что фото сохранено и отображается в карточке.
   Для существующего помещения загрузите новое изображение на странице
   `/rooms/<slug>/edit/`.
7. **Проверки.** Покажите вывод `python manage.py check`,
   `python manage.py showmigrations`, `python manage.py makemigrations --check`,
   `python manage.py test bookings rooms`,
   `python -m pytest -v` и `python -m flake8 . --extend-exclude=venv`.
   Предъявите README и PR9/PR10/PR11 коммиты Git.

## Короткий рассказ

«Roomly хранит помещения, пользователей и бронирования в моделях Django.
Миграции создают структуру базы, а команда импорта переносит данные старой
SQLite-базы, сохраняя идентификаторы и связи. Страницы читают записи через
ORM. Админка позволяет управлять связанными объектами. Формы фильтруют
бронирования и безопасно создают, редактируют и отменяют их с проверкой дат и
занятости помещения».
